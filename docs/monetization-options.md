## 一、核心问题：收费是否必须接入用户系统？

### 直接回答：**不必须。** 取决于你想卖什么。

关键区分点是：**"谁承担订单/权益管理"**。

- 如果让**第三方平台**（爱发电、面包多、Creem、Paddle…）承担订单、收款、退款、用户身份 → 你的站点**不需要任何用户系统**。
- 如果你要让**站点自身**实现"登录后享受不同权益"（会员专区、进度记录、订阅自动续费、防账号分享）→ 就必须有身份与权益服务（可以是极轻的 KV + 兑换码，不一定是完整"注册登录"）。

### 1.1 不接用户系统也能实现的收费模式（站内零改动 / 极低改动）

| 模式                | 机制                                                | 站内是否需要改动     |
| ----------------- | ------------------------------------------------- | ------------ |
| 整体买断 / 转售成品包      | 交付构建产物（Oracle 静态包 / ZIP / Docker 镜像），第三方平台下单后自动发货 | ❌ 不需要        |
| 第三方平台会员 / 赞助      | 在爱发电、Patreon 类平台开"赞助档位"，站点只放一个跳转按钮                | ❌ 不需要（仅超链接）  |
| 打赏 / 捐款           | 收款码 / 平台打赏链接                                      | ❌ 不需要        |
| 私有化部署 / 源码授权（B2B） | 合同 + 对公转账，交付带署名的部署包                               | ❌ 不需要        |
| 白标 / OEM 授权       | 一次性授权费 + 年费，合同驱动                                  | ❌ 不需要        |
| 广告 / 赞助商 / 联盟     | 广告位、赞助商 logo、联盟跳转                                 | 🟢 低（加广告位）   |
| 授权码离线激活           | 交付包内含静态公钥，校验服务端签发的 License 字符串（无需服务器联网校验）         | 🟡 中（签名校验逻辑） |

> **要点**：以上全部可以用"第三方订单号 / 兑换码 / 授权码"作为凭证，**不建账号体系**。

### 1.2 必须接用户系统（或至少接"身份+权益服务"）才能实现的

| 模式                             | 为什么必须                |
| ------------------------------ | -------------------- |
| **订阅制 SaaS**（按月/年自动续费）         | 必须持续识别"这个用户是否仍在订阅期内" |
| **站内分级权益**（免费看基础、付费解锁题库/测验/标注） | 必须知道"你是谁、你买了什么"      |
| **防分享 / 设备数限制 / 内容防盗链**        | 必须服务端校验（否则一次购买可无限转发） |
| **购买记录找回 / 跨设备同步 / 发票与退款自助**   | 必须账号中心               |
| **自动续费、优惠券、邀请返利**              | 必须订单与用户中心            |

### 1.3 ★ 关键辨析：这里的"用户系统"可以轻到什么程度

| 方案                        | 需要什么                            | 是否需要买服务器                           |
| ------------------------- | ------------------------------- | ---------------------------------- |
| 完整注册登录（手机号/邮箱/密码/找回/个人中心） | 数据库 + 鉴权 + 邮件短信服务               | ❌ EdgeOne KV + Cloud Functions 可覆盖 |
| **极轻方案 A：兑换码**            | KV 存"码 → 权益"，下单后第三方human平台/人工发码 | ❌ 同上                               |
| **极轻方案 B：邮箱魔法链接**         | KV 存邮箱 → 权益，登录=点邮件链接            | ❌ 同上                               |
| **极轻方案 C：微信登录**           | 微信开放平台 + 边缘函数换 openid           | ❌ 同上                               |
| **极轻方案 D：离线 License**     | 只要一对密钥，签发/校验均在客户端，**零后端**       | ❌ 连 KV 都不需要                        |

> **结论**：收费与"是否自建用户系统"是**两个独立决策**。可以先用"零用户系统"模式验证付费意愿，再按需上"极轻权益服务"，**永远不必买服务器**。

## 四、推荐路线（按实现成本 / 合规风险 / 收入天花板）

### 🥇 路线 A：第三方平台代收（**首选 · 立刻可做 · 零资质零开发**）

| 维度    | 评估                                |
| ----- | --------------------------------- |
| 实现成本  | 🟢 **极低**（站内只加一个跳转按钮 + 一个"支持我们"页） |
| 合规风险  | 🟢 **低**（收款由持牌平台承担；你只需保留署名与免责声明）  |
| 收入天花板 | 🟡 **中低**（受平台抽成与流量限制）             |
| 适用前提  | 无需注册公司、无需改后端、**无需用户系统**           |

**MVP 落地（≈1 天）**

1. 在**爱发电**开账号 → 建两档：`¥10/月 支持者`、`¥68 一次性买断离线包`。
2. 在**面包多**上架"离线部署包 / 高清素材包"，自动发货。
3. 站点页脚加"支持我们"入口（外链跳转），**保留 LICENSE / ATTRIBUTION / 免责声明**。
4. 给产品起一个新品牌名（避免 "Human Atlas" 商标风险）。
5. （可选）若要海外收入：**放开海外访问** + 在 **Creem** 上架同一商品（支付宝提现）。

---

### 🥈 路线 B：轻量站内会员（**进阶 · 需主体 + 轻后端**）

| 维度    | 评估                                           |
| ----- | -------------------------------------------- |
| 实现成本  | 🟡 **中**（注册个体户 + EdgeOne KV/Cloud Functions） |
| 合规风险  | 🟡 **中**（需解决备案主体与"有偿服务"问题）                   |
| 收入天花板 | 🔴 **高**（订阅 + DLC，可复购）                       |

**MVP 落地（≈1–2 周）**

1. 注册**个体工商户**（经营范围含"技术开发/技术服务/信息服务/设计"）→ 用个体户重新做 ICP 备案。
2. 申请**微信支付商户号**（PC 网站接入，个体户可绑法人私卡）或**支付宝当面付**。
3. EdgeOne **Cloud Function** 接收支付回调 → 写入 **KV**：`兑换码/邮箱 → 权益等级 + 到期时间`。
4. 站点用**兑换码或邮箱魔法链接**解锁付费内容（题库、测验、标注模板）——**不做完整注册登录**。
5. 会员从 `¥9–¥29/月` 起，先做"一次性内容包"再试订阅（降低退款纠纷）。

> 💡 不建议一上来做"自动续费订阅"：与"不做重运营"诉求冲突，退款与客服成本高。**先做一次性买断/内容包**。

---

### 🥉 路线 C：B2B 授权 / 私有化部署（**高天花板 · 重商务轻技术**）

| 维度    | 评估                            |
| ----- | ----------------------------- |
| 实现成本  | 🟢 **低（技术）** / 🔴 **高（商务）**   |
| 合规风险  | 🟢 **低**（合同约束用途，排除医疗场景）       |
| 收入天花板 | 🔴 **最高**（单笔 ¥5,000–¥200,000） |

**MVP 落地（≈1 周做材料，商务周期另计）**

1. 打包"离线部署成品"：`dist` + 静态数据 + 署名与免责文件，附一键部署说明。
2. 准备**一页式商务方案**：能做什么、不能做什么（**明确排除医疗用途**）、授权范围（单机构/单域名/白标）。
3. 目标客户：医学院校、科普馆/科技馆、企业培训部门、教育软件集成商（**OEM/白标**）。
4. 收款走**对公转账 + 合同**，或通过第三方 B2B 平台；**无需任何站内改动与用户系统**。

### 推荐顺序与理由

```
选路线 A  —— 若你想"先验证有没有人愿意付钱"，且不想折腾主体和运维   ← 推荐从这里开始
选路线 B  —— 若你想做长期订阅、愿意注册个体户、能接受少量运营
选路线 C  —— 若你有教育/企业渠道，或希望单笔收入最大化
A + C 组合 —— 最省心的组合：C 赚大钱（B2B），A 收小钱 + 积累口碑
```

- ✅ 代码 MIT + 数据 CC BY 4.0 → **允许商用与转售**，义务仅为署名 + 标明改编。
